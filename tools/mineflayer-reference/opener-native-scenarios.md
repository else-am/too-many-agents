# Native proxy container opener rechecks

Preauthored before implementation. No native checks have run for this fix; root/tester owns the affected live case after rebuilding.

- Open a normal chest through the actual agent hands, hold the same menu open beyond at least two native five-tick rechecks, then close it. Observe actual chest block actions/lid: count 1 while held, then 0 on close; no premature 0 and no wrapped -1/255. Compare inventory/cursor and chest contents before/after: observation alone changes no items.
- Reopen the same chest after closing and hold another >=10 ticks before closing. Its reused counter must again produce 1 then 0, proving the previous close did not leave a negative count.
- Repeat the held-open interval across a successful script return, and with an ordinary physical-tool-opened menu. Count must follow the retained actual menu, not script lease presence. Close normally once; no duplicate decrement or guest count adjustment.
- Native double chest, simultaneous human and agent viewers, and two agent viewers must retain vanilla ownership/range/count behavior; each half recognizes the same CompoundContainer and close removes only its actual viewer. Barrel/ender-chest counters use their own isOwnContainer predicate, not a guessed chest-name rule.
- A closed/removed/dead/transferred body or out-of-query-AABB proxy must not be added. The proxy remains absent from world entity/player lists and unrelated entity queries. Query-observer failure must not throw through the scheduled world tick.

Source: ContainerOpenersCounter.getPlayersWithContainerOpen/recheckOpeners (generated Minecraft1.21.1 lines48–80), ChestMenu constructor/removed (55/106), AgentHands.openMenu/doCloseContainer, and AgentActions.releaseScript (menu survives lease release). The integration appends only GameAccess-owned existing hands to this one native query; native counter/lid/sound/redstone arithmetic remains authoritative. Existing negative counters caused by the prior build are stale fixture state; this change does not globally clamp or repair them.

Focused source/compile evidence: generated bytecode confirms the wrapped invocation is Level.getEntities(EntityTypeTest,AABB,Predicate) inside getPlayersWithContainerOpen; Java21 standalone compilation of the new event/mixin and affected native classes passed. This does not verify mixin application or native counts at runtime. Held-open/second-open/human-coexistence checks remain UNRUN for root/tester.
