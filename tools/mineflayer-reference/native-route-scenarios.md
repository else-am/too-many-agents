# Native selected-route scenarios (authored before implementation)

Lead runs these in the guarded native world through Codex. This file is a test protocol, not evidence of execution. Record body type/age/scale, raw route and snapshot, returned phases/edits, per-tick position/velocity/onGround, before/after blocks, inventory/durability and independent world observations. Use real upstream Move records with optimizePath:false. Never infer trajectory conformance from compilation or a planner probe.

1. Flat and diagonal: adult zombie, stone floor, straight then diagonal adjacent nodes. Arrive supported at each intended tile, no teleport, no native alternative path; compare per-tick displacement. A wall across the selected segment must fail without following an available corridor around it. Excluded neighboring corridor remains unused.
2. Geometry: repeat narrow passage with baby, adult and scaled-wide/tall zombie. Short body uses a low opening; tall body either performs exactly the explicitly listed extra headroom digs or rejects; wide body rejects a doorway narrower than its actual bounding box. No clipping.
3. Shape heights: lower slab, upper slab, stairs and a .5 rise; then a full-block rise. Step uses current maxUpStep; jump is one controlled native impulse with supported landing. Add a ceiling intersecting the jump arc and verify rejection before takeoff. Body with zero jump strength fails a jump but still walks/steps.
4. Gaps: raw parkour edges spanning one, two and three missing floor cells, from rest and with permitted takeoff run-up; test allowSprinting false/true. Record predicted and actual trajectory, takeoff tick and landing. A gap outside the derived reach fails without stepping into it. A lateral pillar/low ceiling on the arc rejects even when both endpoints are free. Never assign expected reach from player constants.
5. State-dependent physics: repeat with jump boost, speed/slowness, ice/honey and changed initial momentum. Unsupported physics must have a named failure, never a fabricated success. Inspect candidate capability bounds against observed attempts. Rabbit/Slime/Drowned must not accidentally inherit a zombie trajectory claim.
6. Drop: selected one/two-block drop, then landing block removed after request. Reject changed relevant cells; ordinary drop lands under gravity with real fall effects. Water catch must use actual fluid/shape state. No hovering while an action awaits completion.
7. Water and ladder: zombie water entry, ascent, descent and exit with recorded canFloat state; ladder up/down including top dismount. Check actual fluid/climb state, native velocity and supported final stance. Do not assume player sneak holds a mob on a ladder. Reject water-sensitive/unsupported bodies explicitly.
8. Dig corridor: pickaxe in declared tool slot, two ordered stone/headroom breaks followed by movement. Only listed coordinates change; survival time, durability and drops are real. Bedrock, missing reach, denied break, changed mining target and removed tool fail precisely without rerouting or replaying a break.
9. Bridge: scaffold in declared slot, exact upstream reference+face placement followed by supported movement. Check exact placed target/state, consumption and returned edit log. Missing scaffold, non-block item, blocked requested face and out-of-reach reference fail without substitute placement. Test an interactive reference with secondary use and a replaceable reference that would redirect placement.
10. Tower: jump:true record beneath actual body, including short/tall/wide geometry and ceiling. Place only after complete body clearance of resulting shape; verify correct support and landing. Keep travel running between jump and placement. Placement denial leaves a named failure with actual world outcome, not a retry.
11. Door/useOne: toggle the explicitly referenced door and verify open state plus both changed door halves. Already-open door is not toggled closed. Iron/denied/obstructed interaction fails without pretending a scaffold placement occurred.
12. Inventory: alternate stone/wood break/place/break using declared tool/scaffold slots and per-break toolSlot overrides. Equip swaps must preserve slot ownership and material identity; counts/durability reflect exact operations. No invented items or silently selected substitute blocks.
13. Bounds: reject oversized nodes/cache/edit count; invalid/fractional/raw coordinates; discontinuous non-parkour edge; unknown snapshot cells; route outside loaded/simulated chunks or body box. A diagonal edge cannot cross forbidden space even if its endpoint is inside. Empty route only succeeds at the observed start.
14. Change/cancel: change a relevant wall/support cell before an edge or edit, move the body away from request.start, cancel before takeoff/midair/during mining/after placement, leave world or expire lease. Lead owns lease/world cancellation and must call stop exactly once. No subsequent owned control or edit runs; unknown edit outcomes are not replayed. Preserve fall simulation via outer integration after cancellation.

Proposed request: {nodes,start:{x,y,z},blocks:{min:[x,y,z],size:[x,y,z],states:[...]},allowSprinting?:boolean,toolSlot?:number,scaffoldingSlot?:number}. Slots use native inventory indices (0..35 or 40), default current selected main hand; tracked across executor equip swaps. Cache indexing is x fastest, z, y. Hard limits: 128 nodes, 128 total edits, 65536 cache cells, 2400 total ticks. Per-edge and mining bounds are reported by implementation. Returned running/completed frames include node,totalNodes,ticks,position,phase and cumulative verified edits. Native live outcomes remain pending.

Integration refinements: optional `toBreak[].toolSlot` overrides the global tool slot; all slots refer to the original request inventory and are remapped after each swap. `requestStop()` finishes the current edge and landing then returns `stopped:true`; before the first edge it stops immediately only at a settled stance. Immediate `stop()` clears controls/mining; outer AgentActions owns passive travel after cancellation. A successful `tick()` calls native travel exactly once, including building/mining waits. Error ticks can fail before travel; outer cancellation must handle subsequent passive physics. Progress also includes `isMining` and `isBuilding`.

Implementation validation: standalone Java 21 compilation against the lead's actual generated NeoForge 21.1.251 jar, existing dependency jars and compiled integration classes passed. No native scenarios above have run in this child. Dry trajectory prediction currently handles inherited ordinary LivingEntity travel/jump with default MoveControl, friction [.6,1], positive gravity and ordinary drag; other control/travel overrides, levitation/slow-falling dry trajectories and context-changing BlockItem subclasses have explicit failures and remain pending work. Native water/climb controls are implemented but not trajectory-conformance tested. Maximum dry prediction is 27 bounded attempts of 100 ticks and a 25 ms deadline (`route_prediction_budget`), with per-tick live collision/state revalidation; total request 2400 ticks, movement edge 240 ticks, cache sweep 8192-cell bounding volume.

15. Capability snapshots at 20 Hz: change jump strength/boost, gravity, sprinting, velocity, scale and supporting block between ordered frames; compare reported bounds with the new inputs. Switch body/control implementations and confirm support classification changes appropriately. Two same-class bodies with different attributes must retain distinct values. Only class method ownership may be cached; instance physics inputs must remain fresh.

16. Water arrival boundary (preauthored for the reported water failure): replay `navigate-water.js` with the same two-deep channel and zombie. For goals (10,-61,0), (12,-61,0), then dry bank (15,-60,0), record every raw node and the post-travel feet position at each completed node. Water nodes must finish inside their actual integer cell; (-61.05547559879075) must never count as Y=-61. The first successful cobblestone placement at (11,-62,0) remains a single verified edit. No sequence of identical completed routes without goal progress; no coordinate snapping or weakened GoalBlock. Repeat from the captured position (10.59901017970889,-61.05547559879075,.5), with the already-placed block and no replay of its edit.
17. Water control and drift: start immediately below and above the destination Y plane, with positive and negative vertical velocity, then repeat one-cell ascent/descent and a supported water exit. Run with navigation canFloat both false and true without the executor changing it. Record native jump/sink impulses and per-tick velocity; the stronger non-floating Mob impulse must not create an endless ascent/descent cycle or a completed node in the wrong cell. A terminal reply is checked after that tick's native travel, including a tick which crosses the goal plane. Cancel/gracefully stop during ascent and retain the existing scoped-release/landing semantics.
18. Shape/climb preservation: rerun the passing first-slab jump, half-step/full-step/drop and ladder ascent/descent/top-dismount fixtures. Fractional supported stances still map to the logical cell above the occupied shape; an airborne position just below an integer plane does not. Include a waterlogged slab and a shallow supported water cell so fluid aiming does not require entering a ceiling or discard a real supported stance. Impossible clearance must fail within the edge bound, never report a false arrival.

Water change validation: Java 21 standalone compilation passed against the lead's generated NeoForge classes and compiled integration classes.
