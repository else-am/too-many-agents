Use minecraft_run for procedures with loops and awaited steps. `code` is an async function body; return a JSON result. Globals: bot, Vec3, goals, Movements, Block, Item, Entity, ChatMessage, MessageBuilder, Recipe, RecipeItem. No imports, filesystem, network, Node globals or credentials. console.log is captured. Await physical operations. Default deadline120s, maximum300s; memory, CPU and output are bounded.

Compatibility is incomplete. Implemented observations: stable entities, typed Blocks/Items, inventory Windows, heldItem, blockAt, findBlock/findBlocks, cursor/visibility queries, world.getBlock/raycast, getExplosionDamages (estimate), players/game, scoreboards/teams, time/health/air/rain and supportFeature. supportFeature describes the Minecraft version, not adapter coverage. Recipe queries use pinned vanilla data; native craft preserves outputs/remainders.

Implemented actions: look/lookAt, dig/canDigBlock/digTime/stopDigging, placeBlock, block/entity activation, equip/unequip, hotbar selection, inventory clicks/transfers/tossing, containers (including horse sneak-interaction), crafting, furnace/enchantment/anvil/villager windows, books and updateSign. Sign updates require first opening the native editor by interaction. Native clicks own slots, cursor and XP. A Window handle expires when its menu closes. Also available: attack/swingArm, item activation/consume, placeEntity, mount/dismount and manual control states. Release manual inputs before Pathfinder navigation. Mob physics remain native. Fishing/sleep/wake verified; elytraFly starts native gliding. Boat steering uses moveVehicle(left, forward), with zero inputs removing acceleration; creative slot set/clear accepts Item components; flight uses native collision; other mounts remain pending. Chat/whisper, patterns and awaitMessage are available; commands require creative_commands mode. tabComplete queries native commands; setCommandBlock requires creative_commands and operator permission.

Pathfinder supplies goto, setGoal (including dynamic goals), setMovements, stop, movement/mining/building queries, bestHarvestTool, getPathTo and synchronous getPathFromTo. Resume partial paths through the planning generator. Configure new Movements(bot), then bot.pathfinder.setMovements(movements). Shortcut/free-motion behavior and full execution conformance remain pending.

Synchronous queries read continuously updated local state: currently a33×17×33 block volume around the body. blockAt returns null outside it or for unloaded cells. on/once/removeListener support physicsTick, blockUpdate, nearby entity changes, entityHurt/entityDead/playerCollect, soundEffectHeard, inventory and state events; complete event conformance remains pending. Stream loss fails the script without reconnecting/replaying.

Digging and placement require existing reach; they do not approach for you. Java executes Pathfinder's selected edges with native collision, tools, permissions and inventory consumption. Snapshot/trajectory checks may reject a route. Ground movement, water, ladders, slabs, jumps, digging and building have focused live checks; specialized species and broader edge cases remain pending. bot.nativeBody exposes current capabilities; jump bounds generate candidates, not guaranteed crossings. Ambient movement is suppressed during scripts while gravity continues.

Example:
const block = bot.findBlock({matching: bot.registry.blocksByName.oak_log.id});
if (!block) throw new Error('No loaded oak log');
await bot.pathfinder.goto(new goals.GoalNear(block.position.x, block.position.y, block.position.z, 2));
await bot.dig(block);
return bot.inventory.items().map(item => ({name:item.name,count:item.count}));

Reports include result, logs, bridge-operation count and actions. Completed mutations remain after failure/cancellation. Missing replies mean unknown outcomes: never automatically replay them. Inspect before further action. Physical tools remain available for unsupported operations but cannot take over a running script. minecraft_cancel stops its current action and releases control.
