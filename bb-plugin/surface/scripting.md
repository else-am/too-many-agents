Use minecraft_run for procedures with loops and awaited steps. `code` is an async function body; use `return` for its JSON result. `bot`, `Vec3`, Pathfinder `goals`, `Movements`, `Block`, `Item`, `Entity`, `ChatMessage`, `MessageBuilder`, `Recipe`, and `RecipeItem` are ready to use. No imports, filesystem, network, Node globals, or bridge credentials are exposed. console.log is captured. Await every physical operation. Default deadline is 120 seconds, maximum 300 seconds; output is bounded. Infinite synchronous execution is interrupted.

Mineflayer compatibility remains incomplete. Available observations include stable entities, typed Blocks and Items, inventory Window queries, heldItem, blockAt, findBlock/findBlocks, and world.getBlock/raycast. Synchronous recipesFor/recipesAll queries use the pinned vanilla recipe table and current inventory; crafting execution remains pending. Physical methods include equip(itemOrType, destination), dig(block), and waitForTicks. Dig look/face options, findBlocks extra-info options, native container clicks, crafting, and other gameplay APIs remain pending; do not assume full upstream support.

Pathfinder provides goto, setGoal (including dynamic goals), setMovements, stop, movement/mining/building queries, bestHarvestTool, getPathTo and the synchronous getPathFromTo generator. Planning can return partial results; resume the generator across ticks for a complete search. Use `new Movements(bot)` to configure digging, scaffolding, exclusions and other policies before `bot.pathfinder.setMovements(movements)`. Upstream goal classes are available. Shortcut/free-motion behavior and full execution conformance remain pending.

Queries are synchronous and read a local view updated continuously while the script runs. It currently includes a 33×17×33 block volume centered on the body; blockAt returns null outside this view or for unloaded blocks. Blocks expose state properties, collision shapes, light, biome ID and client-visible block-entity data. Position and entity references remain stable across updates. `bot.on`/`once`/`removeListener` are available with initial `physicsTick`, `blockUpdate`, and nearby entity spawn/move/gone events; complete event conformance remains pending. A slow or interrupted state stream fails the script rather than silently reconnecting.

Mining requires existing reach and does not walk for you. Pathfinder plans locally and Java executes the selected edges, including requested mining and placement with real tools, reach and inventory consumption. Native collision and snapshot checks can reject an unexecutable route. Ordinary ground-body routes have live coverage; specialized species physics, water/ladder behavior and other edge cases remain under verification. `bot.nativeBody` describes current body capabilities; its jump-distance bounds generate candidates, not guaranteed crossings. Script control suppresses ambient movement between steps while gravity continues; configured behavior resumes when control is released.

Example:
const block = bot.findBlock({ matching: bot.registry.blocksByName.oak_log.id });
if (!block) throw new Error('No loaded oak log in view');
await bot.pathfinder.goto(new goals.GoalNear(block.position.x, block.position.y, block.position.z, 2));
await bot.dig(block);
return bot.inventory.items().map(item => ({ name: item.name, count: item.count }));
